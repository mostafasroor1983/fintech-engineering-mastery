## C01: كائن قيمة للمال مع توزيع عادل

**المسألة.** نفّذ نوع `Money` غير قابل للتغيير يحمل مبلغًا وعملة وفق ISO 4217. وادعم `plus` و`minus` (للعملة نفسها فقط)، والتحليل من نص عشري، و`allocate(int... ratios)`، التي تقسم مبلغًا حسب النسب دون إنشاء أو فقدان وحدة صغرى واحدة.

**الحالات الحدية.** عدم تطابق العملة؛ وخانات عشرية أكثر مما تسمح به العملة (`1.005 GBP`)؛ وعملات بخانتين عشريتين صفر أو ثلاث (JPY، وKWD)؛ والفيضان؛ والمبالغ السالبة؛ ونسب مجموعها صفر أو تتضمن سوالب؛ وتقسيم 100 على ثلاثة (34/33/33).

**النهج.** خزّن الوحدات الصغرى في `long` (دقيق، وسريع، ومساواة بسيطة). والتوزيع: خذ الجزء الصحيح لكل حصة، ثم وزّع الوحدات المتبقية على أكبر البواقي، وحدة لكل منها.

```java
import java.math.BigDecimal;
import java.util.Currency;
import java.util.Objects;

/**
 * C01: an immutable money value object in minor units (pence, cents) with fair allocation.
 *
 * <p>Minor units in a {@code long} avoid floating-point error and make equality exact.
 * Every operation checks the currency and uses {@link Math#addExact} so overflow fails loudly.
 */
public record Money(long minor, Currency currency) {

    public Money {
        Objects.requireNonNull(currency, "currency");
    }

    public static Money of(String amount, String currencyCode) {
        Currency c = Currency.getInstance(currencyCode);
        BigDecimal value = new BigDecimal(amount);   // from a String: exact, never from a double
        // movePointRight + longValueExact rejects more decimals than the currency allows (e.g. 1.005 GBP)
        long minor = value.movePointRight(c.getDefaultFractionDigits()).longValueExact();
        return new Money(minor, c);
    }

    public Money plus(Money other) {
        requireSameCurrency(other);
        return new Money(Math.addExact(minor, other.minor), currency);
    }

    public Money minus(Money other) {
        requireSameCurrency(other);
        return new Money(Math.subtractExact(minor, other.minor), currency);
    }

    public boolean isNegative() {
        return minor < 0;
    }

    /**
     * Splits this amount by ratios without creating or losing a single minor unit
     * (largest-remainder method). Example: 100 by {1, 1, 1} gives 34, 33, 33.
     */
    public Money[] allocate(int... ratios) {
        if (ratios.length == 0) throw new IllegalArgumentException("no ratios");
        long total = 0;
        for (int r : ratios) {
            if (r < 0) throw new IllegalArgumentException("negative ratio");
            total = Math.addExact(total, r);
        }
        if (total == 0) throw new IllegalArgumentException("ratios sum to zero");

        long[] shares = new long[ratios.length];
        long[] remainders = new long[ratios.length];
        long allocated = 0;
        for (int i = 0; i < ratios.length; i++) {
            // multiplyExact: minor * ratio can overflow for huge amounts; fail instead of wrapping
            long product = Math.multiplyExact(minor, (long) ratios[i]);
            shares[i] = Math.floorDiv(product, total);
            remainders[i] = Math.floorMod(product, total);
            allocated += shares[i];
        }
        // Hand out the leftover units one by one to the largest remainders (ties: earliest first)
        long leftover = minor - allocated;
        boolean[] given = new boolean[ratios.length];
        for (long k = 0; k < leftover; k++) {
            int best = -1;
            for (int i = 0; i < ratios.length; i++) {
                if (!given[i] && (best < 0 || remainders[i] > remainders[best])) best = i;
            }
            shares[best]++;
            given[best] = true;
        }
        Money[] out = new Money[ratios.length];
        for (int i = 0; i < ratios.length; i++) out[i] = new Money(shares[i], currency);
        return out;
    }

    private void requireSameCurrency(Money other) {
        if (!currency.equals(other.currency)) {
            throw new IllegalArgumentException("currency mismatch: " + currency + " vs " + other.currency);
        }
    }

    @Override
    public String toString() {
        return BigDecimal.valueOf(minor, currency.getDefaultFractionDigits()).toPlainString() + " " + currency;
    }
}
```
**التعقيد والملاحظات.** ‏`allocate` تعقيدها O(n²) في عدد النسب بسبب حلقة المتبقي (n صغير جدًا؛ واستخدم الفرز لـ n كبير). وهي غير قابلة للتغيير، فهي آمنة للخيوط بالبناء. *أسئلة المتابعة:* "لماذا لا `double`؟" (الكسور الثنائية)؛ و"لماذا `longValueExact`؟" (رفض التقريب الصامت)؛ و"من يحصل على البنس الإضافي؟" (وثّق قاعدة كسر التعادل: الأسبق يفوز).

## C02: مخزن عدم تكرار مع إزالة التكرار للطلبات الجارية

**المسألة.** يجب أن تشغّل `execute(key, requestHash, operation)` العملية مرة واحدة على الأكثر لكل مفتاح حتى حين تصل إعادات المحاولة بالتزامن؛ والمستدعون المتزامنون بالمفتاح نفسه يحصلون على النتيجة نفسها؛ والمفتاح المعاد استخدامه بطلب مختلف يُرفض؛ والإخفاقات لا تُحفظ (حتى تنجح إعادة المحاولة).

**الحالات الحدية.** خمسون طلبًا متطابقًا متزامنًا؛ والمفتاح نفسه بجسم مختلف؛ والعملية ترمي استثناءً (يجب ألا يتعلق المنتظرون ويجب أن يُحرر المفتاح)؛ والعملية ترمي `Error`؛ والمفاتيح الفارغة.

**النهج.** مطالبة ذرية بـ `putIfAbsent` لـ `CompletableFuture`: الفائز يشغّل العملية ويُكمل المستقبل، والآخرون ينتظرونه بـ `join()`.

```java
import java.util.Objects;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.CompletionException;
import java.util.concurrent.ConcurrentHashMap;
import java.util.function.Supplier;

/**
 * C02: run an operation at most once per idempotency key, even when retries arrive concurrently.
 *
 * <ul>
 *   <li>First caller for a key runs the operation; concurrent callers with the same key wait for the
 *       same result instead of running it again (in-flight de-duplication).</li>
 *   <li>Same key with a different request body is a client bug: rejected, never silently replayed.</li>
 *   <li>A failed operation is not remembered, so the client can retry it.</li>
 * </ul>
 * In production the map is a database table with a unique constraint on the key (claimed in the same
 * transaction as the effect) and a retention period; this in-memory version shows the concurrency logic.
 */
public final class IdempotencyStore<T> {

    private record Entry<T>(String requestHash, CompletableFuture<T> result) { }

    private final ConcurrentHashMap<String, Entry<T>> entries = new ConcurrentHashMap<>();

    public T execute(String key, String requestHash, Supplier<T> operation) {
        Objects.requireNonNull(key, "key");
        Objects.requireNonNull(requestHash, "requestHash");

        CompletableFuture<T> mine = new CompletableFuture<>();
        // putIfAbsent is atomic: exactly one caller per key wins the claim
        Entry<T> existing = entries.putIfAbsent(key, new Entry<>(requestHash, mine));

        if (existing != null) {
            if (!existing.requestHash().equals(requestHash)) {
                throw new IdempotencyConflictException(key);
            }
            try {
                return existing.result().join();          // wait for the first caller's outcome
            } catch (CompletionException e) {
                throw unwrap(e);
            }
        }

        try {
            T value = operation.get();
            mine.complete(value);
            return value;
        } catch (RuntimeException | Error e) {             // Errors too, or waiters would hang forever
            entries.remove(key);                           // forget failures so a retry can run again
            mine.completeExceptionally(e);                 // waiting callers see the same failure
            throw e;
        }
    }

    private static RuntimeException unwrap(CompletionException e) {
        return e.getCause() instanceof RuntimeException r ? r : e;
    }

    public static final class IdempotencyConflictException extends RuntimeException {
        public IdempotencyConflictException(String key) {
            super("idempotency key reused with a different request: " + key);
        }
    }
}
```
**التعقيد والملاحظات.** ‏O(1) لكل استدعاء. والمنتظرون يُحجبون على `join()`، وهذا رخيص مع الخيوط الافتراضية. وفي الإنتاج تكون الخريطة جدولًا بمفتاح فريد يُطالب به في المعاملة نفسها التي فيها الأثر الجانبي، مع فترة احتفاظ. *أسئلة المتابعة:* "ماذا لو تعطلت العملية في منتصف التنفيذ؟" (صف IN_PROGRESS يحتاج مهمة استعادة)؛ و"لماذا لا `synchronized`؟" (ستسلسل مفاتيح غير مرتبطة).

## C03: تحويلات متزامنة خالية من الجمود

**المسألة.** نفّذ `transfer(from, to, amount)` بين حسابات في الذاكرة بحيث لا تقع التحويلات المتزامنة في جمود أبدًا، ولا تفقد أموالًا أبدًا، ولا تُنزل رصيدًا تحت الصفر أبدًا.

**الحالات الحدية.** تحويلات باتجاهين متعاكسين تعمل بالتزامن (A→B وB→A)؛ والتحويل إلى الحساب نفسه؛ والحسابات غير المعروفة؛ والمبالغ الصفرية أو السالبة؛ وخيوط كثيرة تستنزف حسابًا واحدًا.

**النهج.** اقفل الحسابين بترتيب عام (حسب المعرّف) فتصبح الدورة مستحيلة؛ وافحص الرصيد وانقل المال وأنت تحمل القفلين.

```java
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.locks.ReentrantLock;

/**
 * C03: thread-safe transfers between in-memory accounts, with no deadlock and no negative balance.
 *
 * <p>Two transfers in opposite directions (A to B, B to A) deadlock if each locks its source first.
 * Locking both accounts in a global order (here: by id) makes a cycle impossible.
 */
public final class TransferService {

    private static final class Account {
        final String id;
        final ReentrantLock lock = new ReentrantLock();
        long balanceMinor;                       // guarded by lock

        Account(String id, long balanceMinor) {
            this.id = id;
            this.balanceMinor = balanceMinor;
        }
    }

    private final Map<String, Account> accounts = new ConcurrentHashMap<>();

    public void open(String id, long initialMinor) {
        if (initialMinor < 0) throw new IllegalArgumentException("negative opening balance");
        if (accounts.putIfAbsent(id, new Account(id, initialMinor)) != null) {
            throw new IllegalArgumentException("account exists: " + id);
        }
    }

    public void transfer(String fromId, String toId, long amountMinor) {
        if (amountMinor <= 0) throw new IllegalArgumentException("amount must be positive");
        if (fromId.equals(toId)) throw new IllegalArgumentException("same account");
        Account from = require(fromId);
        Account to = require(toId);

        // Global lock order by id: every thread locks the "smaller" account first
        Account first = from.id.compareTo(to.id) < 0 ? from : to;
        Account second = first == from ? to : from;

        first.lock.lock();
        try {
            second.lock.lock();
            try {
                if (from.balanceMinor < amountMinor) {
                    throw new InsufficientFundsException(fromId);
                }
                from.balanceMinor -= amountMinor;
                to.balanceMinor += amountMinor;
            } finally {
                second.lock.unlock();
            }
        } finally {
            first.lock.unlock();
        }
    }

    public long balance(String id) {
        Account a = require(id);
        a.lock.lock();
        try {
            return a.balanceMinor;
        } finally {
            a.lock.unlock();
        }
    }

    private Account require(String id) {
        Account a = accounts.get(id);
        if (a == null) throw new IllegalArgumentException("unknown account: " + id);
        return a;
    }

    public static final class InsufficientFundsException extends RuntimeException {
        public InsufficientFundsException(String accountId) {
            super("insufficient funds in " + accountId);
        }
    }
}
```
**التعقيد والملاحظات.** ‏O(1) لكل تحويل؛ والتحويلات على أزواج حسابات منفصلة تعمل بالتوازي. ويشغّل الاختبار 10,000 تحويل باتجاهين متعاكسين ويتحقق من حفظ الأموال. *أسئلة المتابعة:* "كيف تفعل هذا في قاعدة بيانات؟" (معاملة واحدة بـ `SELECT … FOR UPDATE` مرتبة حسب المعرّف، أو تحديثات مشروطة)؛ و"ماذا عن `tryLock` بمهلة؟" (يتجنب الجمود لكنه يحتاج إعادة محاولة وتراجعًا).

## C04: محدد معدل بدلو الرموز

**المسألة.** محدد آمن للخيوط يسمح باندفاعات حتى `capacity` ويُعاد ملؤه بمعدل `refillPerSecond`؛ و`tryAcquire(n)` لا تحجب أبدًا؛ ويبلّغ أيضًا عن المدة حتى تتوفر `n` تصاريح (من أجل `Retry-After`).

**الحالات الحدية.** فترات خمول طويلة (الرموز محدودة بالسعة)؛ ومعدلات إعادة ملء كسرية؛ وطلبات تصاريح أكثر من السعة؛ والتنافس من خيوط كثيرة؛ وسلوك الساعة (استخدم ساعة رتيبة قابلة للحقن).

**النهج.** إعادة ملء كسولة عند كل استدعاء: الرموز += الوقت المنقضي × المعدل، مع الحد الأقصى؛ وحالة متزامنة.

```java
import java.util.function.LongSupplier;

/**
 * C04: a thread-safe token bucket: bursts up to {@code capacity}, refilled at a steady rate.
 *
 * <p>The clock is injected (nanoseconds, monotonic like {@link System#nanoTime}) so tests are
 * deterministic. Tokens are tracked as a double so slow rates (0.5/s) still refill smoothly.
 */
public final class TokenBucket {

    private final long capacity;
    private final double refillPerNano;
    private final LongSupplier nanoClock;

    private double tokens;          // guarded by this
    private long lastRefillNanos;   // guarded by this

    public TokenBucket(long capacity, double refillPerSecond, LongSupplier nanoClock) {
        if (capacity <= 0) throw new IllegalArgumentException("capacity must be positive");
        if (refillPerSecond <= 0) throw new IllegalArgumentException("refill rate must be positive");
        this.capacity = capacity;
        this.refillPerNano = refillPerSecond / 1_000_000_000.0;
        this.nanoClock = nanoClock;
        this.tokens = capacity;                       // start full
        this.lastRefillNanos = nanoClock.getAsLong();
    }

    /** Takes {@code permits} tokens if all are available; never blocks. */
    public synchronized boolean tryAcquire(int permits) {
        if (permits <= 0 || permits > capacity) throw new IllegalArgumentException("permits out of range");
        refill();
        if (tokens >= permits) {
            tokens -= permits;
            return true;
        }
        return false;
    }

    /** Nanoseconds until {@code permits} tokens will be available (0 if they are now): for Retry-After. */
    public synchronized long nanosUntilAvailable(int permits) {
        refill();
        double missing = permits - tokens;
        return missing <= 0 ? 0 : (long) Math.ceil(missing / refillPerNano);
    }

    private void refill() {
        long now = nanoClock.getAsLong();
        long elapsed = now - lastRefillNanos;          // nanoTime-style values: compare by difference
        if (elapsed > 0) {
            tokens = Math.min(capacity, tokens + elapsed * refillPerNano);
            lastRefillNanos = now;
        }
    }
}
```
**التعقيد والملاحظات.** ‏O(1). و`synchronized` كافٍ لدلو واحد؛ ولملايين المفاتيح استخدم `ConcurrentHashMap` من الدلاء، أو Redis مع سكربت Lua حين يجب أن يصمد الحد عبر النسخ. *أسئلة المتابعة:* "النسخة الموزعة؟" (سكربت Redis يستخدم وقت الخادم)؛ و"الفتح أم الإغلاق عند الفشل؟" (العدالة مقابل الأمان).

## C05: دفتر أستاذ بالقيد المزدوج

**المسألة.** قيّد مُدخلات يومية مكونة من قيود بإشارات؛ وارفض المُدخلات ذات القيدين الأقل من اثنين أو غير المتوازنة **لكل عملة**؛ وتقييد المُدخل نفسه مرتين لا أثر له؛ وإعادة استخدام معرّف لمُدخل مختلف خطأ؛ والأرصدة مشتقة من القيود.

**الحالات الحدية.** مُدخلات صرف متعددة العملات (كل عملة تتوازن منفصلة)؛ والمُدخلات غير المتوازنة؛ والقيود بمبلغ صفري؛ وإعادات التشغيل؛ وإعادة استخدام المعرّف؛ والفيضان في الأرصدة.

```java
import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Objects;

/**
 * C05: a double-entry ledger. Every journal entry has at least two postings and, per currency,
 * its postings sum to zero. Balances are derived from postings; nothing is ever updated in place.
 * Posting the same entry id twice is a no-op (idempotent), posting a different entry under a used
 * id is rejected.
 */
public final class Ledger {

    /** A signed posting: positive = debit, negative = credit (one convention, used everywhere). */
    public record Posting(String account, String currency, long amountMinor) {
        public Posting {
            Objects.requireNonNull(account);
            Objects.requireNonNull(currency);
            if (amountMinor == 0) throw new IllegalArgumentException("zero posting");
        }
    }

    public record JournalEntry(String id, String description, List<Posting> postings) {
        public JournalEntry {
            Objects.requireNonNull(id);
            postings = List.copyOf(postings);          // defensive copy: records are only shallowly immutable
        }
    }

    private final Map<String, JournalEntry> entries = new HashMap<>();
    private final Map<String, Long> balances = new HashMap<>();   // key: account|currency
    private final List<JournalEntry> journal = new ArrayList<>();

    /** Returns true if posted now, false if this exact entry was already posted. */
    public synchronized boolean post(JournalEntry entry) {
        JournalEntry previous = entries.get(entry.id());
        if (previous != null) {
            if (previous.equals(entry)) return false;  // idempotent replay
            throw new IllegalStateException("entry id reused with different content: " + entry.id());
        }
        validate(entry);
        for (Posting p : entry.postings()) {
            balances.merge(p.account() + "|" + p.currency(), p.amountMinor(), Math::addExact);
        }
        entries.put(entry.id(), entry);
        journal.add(entry);
        return true;
    }

    public synchronized long balance(String account, String currency) {
        return balances.getOrDefault(account + "|" + currency, 0L);
    }

    public synchronized List<JournalEntry> journal() {
        return List.copyOf(journal);
    }

    private static void validate(JournalEntry entry) {
        if (entry.postings().size() < 2) {
            throw new IllegalArgumentException("an entry needs at least two postings");
        }
        Map<String, Long> perCurrency = new HashMap<>();
        for (Posting p : entry.postings()) {
            perCurrency.merge(p.currency(), p.amountMinor(), Math::addExact);
        }
        perCurrency.forEach((currency, sum) -> {
            if (sum != 0) {
                throw new IllegalArgumentException("unbalanced in " + currency + ": " + sum);
            }
        });
    }
}
```
**التعقيد والملاحظات.** ‏O(p) لكل مُدخل لـ p قيدًا. والقفل الواحد يُبقي المثال بسيطًا؛ ودفتر الأستاذ الحقيقي يستخدم معاملات قاعدة البيانات، ومشغّل قيد مؤجل لقاعدة التوازن، ومفتاحًا فريدًا على معرّف المُدخل. *أسئلة المتابعة:* "كيف تصحح مُدخلًا خاطئًا؟" (عكس مع مُدخل جديد)؛ و"كيف توسّع الحسابات الساخنة؟" (حسابات فرعية، وإيداعات مجمّعة في مخزن).
