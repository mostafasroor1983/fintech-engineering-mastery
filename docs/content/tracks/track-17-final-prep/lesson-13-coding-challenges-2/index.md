## C06: Reconciliation matcher

**Problem.** Match bank statement lines to ledger items and classify everything left over. Pass 1 matches by exact reference (same amount and currency). Pass 2 matches by amount, currency and value date within a tolerance, **only when there is exactly one candidate**. Leftovers are breaks: missing in ledger, missing at bank, or ambiguous.

**Edge cases.** Two ledger items with the same amount and date (ambiguous: never auto-match); a reference that appears on two ledger items (don't trust it); a reference match with a different amount; currency mismatch; dates just outside the tolerance; each line and item used at most once.

```java
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.ArrayList;
import java.util.HashMap;
import java.util.HashSet;
import java.util.List;
import java.util.Map;
import java.util.Set;

/**
 * C06: match bank statement lines to ledger items and classify everything left over as a break.
 *
 * <ol>
 *   <li>Pass 1: exact end-to-end reference (and same amount and currency).</li>
 *   <li>Pass 2: same amount and currency, value dates within a tolerance, and exactly ONE candidate.
 *       Two or more candidates are AMBIGUOUS and go to a human: a wrong auto-match hides two real breaks.</li>
 * </ol>
 * Each line and each item is used at most once.
 */
public final class Reconciler {

    public record BankLine(String id, String reference, long amountMinor, String currency, LocalDate valueDate) { }

    public record LedgerItem(String id, String reference, long amountMinor, String currency, LocalDate valueDate) { }

    public record Match(BankLine line, LedgerItem item, String rule) { }

    public enum BreakType { MISSING_IN_LEDGER, MISSING_AT_BANK, AMBIGUOUS }

    public record Break(BreakType type, String id, String detail) { }

    public record Result(List<Match> matches, List<Break> breaks) { }

    private final int dateToleranceDays;

    public Reconciler(int dateToleranceDays) {
        if (dateToleranceDays < 0) throw new IllegalArgumentException("negative tolerance");
        this.dateToleranceDays = dateToleranceDays;
    }

    public Result reconcile(List<BankLine> lines, List<LedgerItem> items) {
        List<Match> matches = new ArrayList<>();
        List<Break> breaks = new ArrayList<>();
        Set<String> usedItems = new HashSet<>();
        List<BankLine> unmatched = new ArrayList<>();

        // Pass 1: reference index (references that appear on more than one item are not trusted)
        Map<String, List<LedgerItem>> byRef = new HashMap<>();
        for (LedgerItem i : items) {
            if (i.reference() != null && !i.reference().isBlank()) {
                byRef.computeIfAbsent(i.reference(), k -> new ArrayList<>()).add(i);
            }
        }
        for (BankLine l : lines) {
            List<LedgerItem> c = l.reference() == null ? List.of() : byRef.getOrDefault(l.reference(), List.of());
            LedgerItem hit = c.size() == 1 ? c.get(0) : null;
            if (hit != null && !usedItems.contains(hit.id()) && sameMoney(l, hit)) {
                matches.add(new Match(l, hit, "REFERENCE"));
                usedItems.add(hit.id());
            } else {
                unmatched.add(l);
            }
        }

        // Pass 2: amount + currency + date window, only when unambiguous
        for (BankLine l : unmatched) {
            List<LedgerItem> candidates = items.stream()
                    .filter(i -> !usedItems.contains(i.id()))
                    .filter(i -> sameMoney(l, i))
                    .filter(i -> Math.abs(ChronoUnit.DAYS.between(l.valueDate(), i.valueDate())) <= dateToleranceDays)
                    .toList();
            if (candidates.size() == 1) {
                matches.add(new Match(l, candidates.get(0), "AMOUNT_DATE"));
                usedItems.add(candidates.get(0).id());
            } else if (candidates.isEmpty()) {
                breaks.add(new Break(BreakType.MISSING_IN_LEDGER, l.id(), "no ledger item"));
            } else {
                breaks.add(new Break(BreakType.AMBIGUOUS, l.id(), candidates.size() + " candidates"));
            }
        }

        for (LedgerItem i : items) {
            if (!usedItems.contains(i.id())) breaks.add(new Break(BreakType.MISSING_AT_BANK, i.id(), "not on statement"));
        }
        return new Result(List.copyOf(matches), List.copyOf(breaks));
    }

    private static boolean sameMoney(BankLine l, LedgerItem i) {
        return l.amountMinor() == i.amountMinor() && l.currency().equals(i.currency());
    }
}
```
**Complexity and notes.** Pass 2 is O(lines × items) here; in production, index candidates by (currency, amount) in a map so each lookup is O(k) for k candidates. Record the rule that matched for audit. *Follow-ups:* many-to-one matches (one bank line paying several invoices); tolerance for fees netted by the bank.

## C07: Card velocity check (sliding window)

**Problem.** Decline an authorisation if, for that card, the number of authorisations or their total amount within the last `window` would exceed the limits. Approved authorisations are recorded; declined ones aren't.

**Edge cases.** An event exactly at the window boundary; many cards (memory per card stays bounded); concurrent checks on one card (the count must hold); out-of-order timestamps (assume ordered per card, or note it as a follow-up).

```java
import java.time.Duration;
import java.time.Instant;
import java.util.ArrayDeque;
import java.util.Deque;
import java.util.concurrent.ConcurrentHashMap;

/**
 * C07: a sliding-window velocity rule for card fraud: "at most N authorisations and at most X in
 * value per card in the last W". Each card keeps a deque of recent events; old ones are evicted on
 * every call, so memory per card is bounded by the events inside the window.
 *
 * <p>A declined attempt is not recorded: it did not spend anything. Locking is per card, so cards do
 * not contend with each other.
 */
public final class VelocityChecker {

    private record Event(Instant at, long amountMinor) { }

    private static final class Window {
        final Deque<Event> events = new ArrayDeque<>();
        long totalMinor;
    }

    public enum Decision { ALLOW, DECLINE_COUNT, DECLINE_AMOUNT }

    private final Duration window;
    private final int maxCount;
    private final long maxAmountMinor;
    private final ConcurrentHashMap<String, Window> cards = new ConcurrentHashMap<>();

    public VelocityChecker(Duration window, int maxCount, long maxAmountMinor) {
        if (window.isNegative() || window.isZero()) throw new IllegalArgumentException("window must be positive");
        this.window = window;
        this.maxCount = maxCount;
        this.maxAmountMinor = maxAmountMinor;
    }

    public Decision check(String cardId, long amountMinor, Instant at) {
        if (amountMinor <= 0) throw new IllegalArgumentException("amount must be positive");
        Window w = cards.computeIfAbsent(cardId, k -> new Window());
        synchronized (w) {
            Instant cutoff = at.minus(window);
            // Evict events that are out of the window: (at - W, at] stays
            while (!w.events.isEmpty() && !w.events.peekFirst().at().isAfter(cutoff)) {
                w.totalMinor -= w.events.pollFirst().amountMinor();
            }
            if (w.events.size() + 1 > maxCount) return Decision.DECLINE_COUNT;
            if (w.totalMinor + amountMinor > maxAmountMinor) return Decision.DECLINE_AMOUNT;
            w.events.addLast(new Event(at, amountMinor));
            w.totalMinor += amountMinor;
            return Decision.ALLOW;
        }
    }
}
```
**Complexity and notes.** Amortised O(1) per check (each event is added and evicted once); memory is O(events in the window) per card. Locking is per card. Idle cards keep their deque forever here; production needs eviction (Caffeine with expiry) or a Redis sorted set per card. *Follow-ups:* distributed version, out-of-order events, and limits in multiple currencies.

## C08: Retry with capped exponential backoff and full jitter

**Problem.** Retry a call only for retryable errors, up to `maxAttempts`, waiting a random delay in `[0, min(cap, base × 2^attempt)]` (full jitter), and give up early if the next delay would exceed an overall deadline. Preserve interruption.

**Edge cases.** Non-retryable error on the first attempt (no retry); the last attempt fails (rethrow the real error); the deadline reached before max attempts; interruption during sleep; shift overflow for large attempt counts.

```java
import java.time.Duration;
import java.util.concurrent.Callable;
import java.util.function.LongSupplier;
import java.util.function.Predicate;
import java.util.random.RandomGenerator;

/**
 * C08: retries with capped exponential backoff and full jitter, a maximum number of attempts and an
 * overall deadline. Only errors the caller marks as retryable are retried: never retry a non-idempotent
 * call that might already have succeeded.
 *
 * <p>Full jitter: delay = random(0, min(cap, base * 2^attempt)). It spreads retries from many
 * clients so they don't hit the recovering service in synchronised waves.
 */
public final class Retrier {

    /** Sleeping is injected so tests run instantly and can record the delays. */
    public interface Sleeper {
        void sleep(Duration d) throws InterruptedException;
    }

    private final int maxAttempts;
    private final Duration base;
    private final Duration cap;
    private final Duration deadline;
    private final Predicate<Exception> retryable;
    private final Sleeper sleeper;
    private final RandomGenerator random;
    private final LongSupplier nanoClock;

    public Retrier(int maxAttempts, Duration base, Duration cap, Duration deadline,
                   Predicate<Exception> retryable, Sleeper sleeper, RandomGenerator random, LongSupplier nanoClock) {
        if (maxAttempts < 1) throw new IllegalArgumentException("maxAttempts must be >= 1");
        this.maxAttempts = maxAttempts;
        this.base = base;
        this.cap = cap;
        this.deadline = deadline;
        this.retryable = retryable;
        this.sleeper = sleeper;
        this.random = random;
        this.nanoClock = nanoClock;
    }

    public <T> T call(Callable<T> action) throws Exception {
        long start = nanoClock.getAsLong();
        for (int attempt = 1; ; attempt++) {
            try {
                return action.call();
            } catch (Exception e) {
                if (!retryable.test(e) || attempt >= maxAttempts) throw e;
                long backoffCap = Math.min(cap.toNanos(), base.toNanos() << Math.min(attempt - 1, 30));
                long delay = random.nextLong(backoffCap + 1);          // full jitter: [0, backoffCap]
                long remaining = deadline.toNanos() - (nanoClock.getAsLong() - start);
                if (delay >= remaining) throw e;                         // would miss the deadline: give up now
                try {
                    sleeper.sleep(Duration.ofNanos(delay));
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();                  // keep the interrupt for the caller
                    e.addSuppressed(ie);
                    throw e;
                }
            }
        }
    }
}
```
**Complexity and notes.** No shared state, so it's thread-safe. Inject the sleeper, clock and random source so tests are instant and deterministic. Full jitter de-synchronises clients and prevents retry waves. *Follow-ups:* retry budgets across a fleet; honouring `Retry-After`; why you must never retry a non-idempotent POST without an idempotency key.

## C09: Consistent hashing with virtual nodes

**Problem.** Map keys (account ids) to nodes so that adding or removing a node moves only about 1/N of the keys, with even load.

**Edge cases.** An empty ring; wrap-around past the largest hash; removing a node returns its keys to neighbours only; hash collisions between nodes; stable hashing across JVMs (don't use `String.hashCode` distribution assumptions).

```java
import java.nio.ByteBuffer;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.util.Map;
import java.util.SortedMap;
import java.util.TreeMap;

/**
 * C09: consistent hashing with virtual nodes, to spread accounts over partitions or cache nodes.
 *
 * <p>Each physical node owns {@code virtualNodes} points on a 64-bit ring. A key belongs to the first
 * point clockwise from its hash. Adding or removing one of N nodes moves only about 1/N of the keys,
 * where {@code hash % N} would move almost all of them.
 */
public final class ConsistentHashRing {

    private final int virtualNodes;
    private final TreeMap<Long, String> ring = new TreeMap<>();

    public ConsistentHashRing(int virtualNodes) {
        if (virtualNodes < 1) throw new IllegalArgumentException("virtualNodes must be >= 1");
        this.virtualNodes = virtualNodes;
    }

    public synchronized void addNode(String node) {
        for (int i = 0; i < virtualNodes; i++) {
            String previous = ring.putIfAbsent(hash(node + "#" + i), node);
            if (previous != null && !previous.equals(node)) {
                throw new IllegalStateException("hash collision between " + previous + " and " + node);
            }
        }
    }

    public synchronized void removeNode(String node) {
        for (int i = 0; i < virtualNodes; i++) ring.remove(hash(node + "#" + i), node);
    }

    public synchronized String nodeFor(String key) {
        if (ring.isEmpty()) throw new IllegalStateException("no nodes");
        SortedMap<Long, String> tail = ring.tailMap(hash(key));
        return tail.isEmpty() ? ring.firstEntry().getValue() : tail.get(tail.firstKey());  // wrap around
    }

    public synchronized Map<Long, String> snapshot() {
        return Map.copyOf(ring);
    }

    /** First 8 bytes of SHA-256: stable across JVMs and runs, unlike String.hashCode distribution. */
    static long hash(String s) {
        try {
            byte[] d = MessageDigest.getInstance("SHA-256").digest(s.getBytes(StandardCharsets.UTF_8));
            return ByteBuffer.wrap(d, 0, 8).getLong();
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException(e);   // every JVM must provide SHA-256
        }
    }
}
```
**Complexity and notes.** Lookup O(log V) for V virtual points (`TreeMap.tailMap`); adding a node O(v log V). The test checks that adding a 5th node moves 12–28% of 20,000 keys (ideal 20%) and that moved keys only go to the new node. *Follow-ups:* weighted nodes (more virtual nodes for bigger machines); replication to the next R distinct nodes; how Kafka (fixed partitions) differs.

## C10: Circuit breaker

**Problem.** CLOSED counts consecutive failures; at the threshold it OPENs and fails fast. After the open duration, HALF_OPEN lets exactly one trial call through: success closes it, failure re-opens it. Calls run outside the lock.

**Edge cases.** Concurrent calls in HALF_OPEN (only one probe); a slow call that started while CLOSED and succeeds after the breaker opened (must **not** close it); a late failure from before opening (must not refresh the open timer); the clock injected.

```java
import java.time.Duration;
import java.util.concurrent.Callable;
import java.util.function.LongSupplier;

/**
 * C10: a circuit breaker. CLOSED counts consecutive failures; at the threshold it OPENs and fails
 * fast. After the open duration it lets exactly ONE trial call through (HALF_OPEN): success closes
 * it, failure opens it again. Fail-fast protects threads, pools and the struggling dependency.
 */
public final class CircuitBreaker {

    public enum State { CLOSED, OPEN, HALF_OPEN }

    private final int failureThreshold;
    private final long openNanos;
    private final LongSupplier nanoClock;

    private State state = State.CLOSED;     // guarded by this
    private int consecutiveFailures;        // guarded by this
    private long openedAt;                  // guarded by this
    private boolean trialInFlight;          // guarded by this

    public CircuitBreaker(int failureThreshold, Duration openDuration, LongSupplier nanoClock) {
        if (failureThreshold < 1) throw new IllegalArgumentException("threshold must be >= 1");
        this.failureThreshold = failureThreshold;
        this.openNanos = openDuration.toNanos();
        this.nanoClock = nanoClock;
    }

    public <T> T call(Callable<T> action) throws Exception {
        boolean trial = acquirePermission();      // throws CallNotPermittedException when open
        try {
            T result = action.call();             // the call runs OUTSIDE the lock
            onSuccess(trial);
            return result;
        } catch (Exception e) {
            onFailure(trial);
            throw e;
        }
    }

    public synchronized State state() {
        return state;
    }

    private synchronized boolean acquirePermission() {
        if (state == State.OPEN && nanoClock.getAsLong() - openedAt >= openNanos) {
            state = State.HALF_OPEN;
        }
        return switch (state) {
            case CLOSED -> false;
            case OPEN -> throw new CallNotPermittedException();
            case HALF_OPEN -> {
                if (trialInFlight) throw new CallNotPermittedException();   // only one probe at a time
                trialInFlight = true;
                yield true;
            }
        };
    }

    private synchronized void onSuccess(boolean trial) {
        if (trial) {                            // the probe worked: the dependency is back
            state = State.CLOSED;
            trialInFlight = false;
        }
        // A slow call that started while CLOSED and succeeds after the breaker opened must not
        // close it again: only the half-open probe decides that.
        if (state == State.CLOSED) consecutiveFailures = 0;
    }

    private synchronized void onFailure(boolean trial) {
        if (trial) {                            // the probe failed: stay away for another open period
            open();
        } else if (state == State.CLOSED && ++consecutiveFailures >= failureThreshold) {
            open();
        }
        // Late failures of calls that started before the breaker opened change nothing.
    }

    private void open() {
        state = State.OPEN;
        openedAt = nanoClock.getAsLong();
        consecutiveFailures = 0;
        trialInFlight = false;
    }

    public static final class CallNotPermittedException extends RuntimeException {
        public CallNotPermittedException() {
            super("circuit open: call not permitted");
        }
    }
}
```
**Complexity and notes.** O(1); the lock is held only for state transitions, never during the call. Production breakers use sliding windows (failure rate over the last N calls or seconds) and slow-call thresholds; Resilience4j is the usual choice. *Follow-ups:* what the fallback is for a payment call (an "unknown, check later" status, not "failed"); combining with retries and bulkheads.
